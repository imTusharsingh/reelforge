# Reusable Prompt: Scope / Architecture Change Request

Do not implement the proposed change immediately. Prepare a change request for the Project Owner and Core Architect/Reviewer.

Include:

1. Change ID and proposer.
2. Problem being solved and evidence that it exists.
3. Requested behavior and user impact.
4. Why the existing frozen v1 scope cannot solve it.
5. Modules, database models, APIs, events, prompts, and pipelines affected.
6. Security, privacy, policy, provider, cost, and operational impact.
7. Backward compatibility and migration plan.
8. New tests and acceptance criteria.
9. What must be removed, deferred, or re-prioritized to keep scope bounded.
10. Recommendation: reject, defer to later release, or approve for v1.

Until the request is approved and recorded in `docs/DECISION_LOG.md`, treat it as out of scope.
