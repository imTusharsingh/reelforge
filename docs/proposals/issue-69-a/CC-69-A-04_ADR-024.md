# CC-69-A-04 / proposed ADR-024 — compatible audit paging and fatal-process safety

**Status: PENDING. ADR-019 remains approved and unchanged unless this proposal is explicitly accepted.**

## CHANGE_CONTROL proposal

- **Change ID/class:** CC-69-A-04; correctness/security/reliability and narrowly scoped worker bootstrap separation.
- **Problem/evidence:** AuditService.list uses occurredAt < before despite ordering by occurredAt/id, losing ties. PostgreSQL stores timestamptz(6), so JS Date-only cursors can also lose sub-millisecond rows. Emergency-stop first-insert conflicts can escape as 500; mid-step stops pass through ordinary workflow failure classification; manual 409 says budget policy. serializeError includes Prisma argument dumps; plain local paths are not masked. Fatal handler writes then immediately exits. Worker main statically imports heavy factories before installing handlers.
- **Proposed behavior:** Add exact-time opaque audit continuation without breaking old response; typed stop pause/409 fixes; redaction; flush-aware bounded fatal exit; handler-first dynamic worker startup; transaction-aware owning audit seam for ADR-022 recovery.
- **User/business value:** Complete tie-aware audit traversal, honest stoppage, reduced sensitive error leakage and visible import-time failures without hanging indefinitely.
- **Affected modules/APIs/schemas/events/prompts/pipelines:** M19 admin/audit/stops, M16 workflow stop catch, observability logger and worker entry. Additive cursor/header and internal audit seam; no DB schema change in this ADR, no new workflow state, no creative prompt/provider/event payload changes.
- **Cost/security/privacy/policy/reliability impact:** Audit reads use parameterized keysets and existing indexes; flush tracks sink completion. OWNER/tenant boundary remains; credentials, raw Prisma arguments and sensitive paths must not escape. A permanently blocked output pipe cannot be guaranteed durable logging. No new dependency, process manager, retention or infrastructure assumption.
- **Backward compatibility/migration:** Existing route, array shape, filters and before remain; cursor is opt-in. Synchronous logger APIs/sinks remain supported. Worker runtime behavior/shutdown is moved, not redesigned. No schema migration or global stop API.
- **Acceptance criteria/tests:** T24-01..12 below, unexecuted.
- **Trade-offs/deferred:** Cursor is a live-feed traversal, not an MVCC snapshot across HTTP calls. Legacy before remains tie-lossy. Fatal flush is bounded best effort, not fsync/delivery proof. Arbitrary failure while importing the minimal observability module cannot be caught by handlers that do not yet exist. General M16 claim-token/concurrency refactor, metrics aggregation, retention and unrelated audit semantics remain out of scope.
- **Owner decision:** No owner choice on the proposed 2,000 ms flush bound is recorded. A-POL-01/02 do not approve this ADR. ADR-019 OWNER/admin and existing PAUSED semantics remain binding.
- **Core Reviewer decision:** PENDING. Minu [#6831527297](https://github.com/imTusharsingh/reelforge/issues/69#issuecomment-6831527297) requires exact cursor compatibility/concurrency, bounded flush/pre-import setup, redaction and failure injection.

## ADR-024 proposed decision

### 1. Alternatives

Audit: offset paging is unstable under concurrent inserts; timestamp-only loses ties. Recommend optional opaque exact `(occurredAt,id)` cursor rather than changing the v1 array into a new envelope. A query ID alongside before is possible, but lacks self-contained purpose/filter/precision validation.

Fatal exit: immediate exit can truncate accepted output; unlimited await can hang the worker. Recommend callback-aware logger flush with a proposed 2,000 ms maximum. Synchronous fallback writes can block on pipes and are not selected. No OTel/logger dependency upgrade is required.

### 2. Exact additive audit API contract

Retain `GET /api/v1/workspaces/:workspaceId/admin/audit-events`, existing OWNER guard, `AuditEventView[]` body, category filter, limit 1..200/default 50, and optional `before` ISO timestamp. Add `cursor` as an optional mutually exclusive alternative to before. Unknown/malformed fields are 400, not generic 500. Other admin/usage audit APIs remain unchanged.

Cursor: canonical base64url encoding of UTF-8 JSON, decoded length at most 512 bytes, strict keys `{v:1,purpose:"admin-audit",workspaceId,category:null|AuditCategory,at,id}`. `at` is canonical UTC `YYYY-MM-DDTHH:mm:ss.ffffffZ`, validated including actual calendar date; id is canonical UUID. Reject oversized/noncanonical/base64-invalid/unknown-version/purpose/filter/workspace mismatch. It is not an authentication token and contains no secret. A tampered boundary may choose a different position only inside an already authorized tenant/filter; use parameterized SQL, never interpolation. No signing secret/KMS choice is introduced.

Order descending by occurred_at then UUID id. Bound next page by `occurred_at < at OR (occurred_at = at AND id < id)` with workspace/category enforced independently of cursor contents. Query limit+1. Build continuation from the last returned row only when another row was observed. Response header `X-Reelforge-Audit-Next-Cursor` is present then, absent on final page. Body remains exactly the existing array. No frontend edit. New internal `AuditService.listPage(context,query) -> {items,nextCursor}`; existing list can delegate and return items for old internal consumers.

Generate the cursor timestamp from PostgreSQL exact microsecond UTC text, not JS Date.toISOString. Existing body occurredAt representation remains unchanged for compatibility. Cursor SQL casts the validated timestamp as timestamptz using a parameter. Existing before semantics are retained and explicitly documented as legacy; only cursor traversal receives the tie-aware guarantee.

Concurrent insert semantics: each request reads a live statement snapshot, not a multi-page stable historical snapshot. Existing rows below the boundary are not duplicated/skipped because timestamps tie. A newly inserted row above the boundary appears on a refreshed first page, not a later older page. A backdated row below the boundary may appear later; one committed after its position was already passed can be missed until traversal restarts. No UUID ordering is treated as insertion time and no cross-request MVCC guarantee is invented. Clients wanting a fresh view restart at page one. Do not add hidden retention/snapshot TTL.

### 3. M19 stop compatibility and owning audit seam

R6: only a trusted typed EmergencyStopError known to be raised before provider dispatch takes the PAUSED path. Propagate that refusal distinctly from optional M11/M15 AI-unavailable fallback. Under the existing workspace/step/lease-owner/attempt CAS fence, transition the active run to existing PAUSED with pausedReason EMERGENCY_STOP and nextAction clear-then-resume; put the claimed step back into its resumable queued state, close the claimed workflow job as CANCELED/EMERGENCY_STOP, clear leases/heartbeat, release concurrency slots and append pause event transactionally. No new run state, automatic resume, canceled-run resurrection or polling block. Existing cancellation/state change wins if the fence no longer matches.

Retain monotonically increasing claim/attempt fencing; do not decrement an attempt and reuse a stale fence. A pre-dispatch stop does not create a PaidAiOperation attempt or spend. This proposal does not grant extra automatic retries beyond existing workflow limits. Test explicit resume with remaining attempts; if repeated interruption exhausts an existing workflow claim budget, report that existing limit rather than quietly raising it. Any alternative counter policy requires a separate Core decision. Safe WAITING_EXTERNAL polls, reconciliation, reads and recovery sweeps remain allowed under ADR-019.

R7: manual start refusal caused by stop returns 409 with code EMERGENCY_STOP and action-specific stop wording; budget exhaustion retains its own code/message. R10: narrowly map Prisma unique violation of the same emergency-stop workspace/scope key during initial creation to 409; do not mask unrelated DB failures. Retain expectedVersion CAS and winner-only audit.

Proposed internal `AuditService.recordTx(tx,entry) -> AuditEventView`: reuse existing entry validation, UUID/correlation rules and redaction, but write using the supplied transaction without nested commit or swallowed error. It is used only by approved bounded M17 replay so notification insert and its audit either both commit or both roll back. Existing best-effort HTTP audit behavior and public record API remain unchanged; this does not implement unrelated transactional audit refactors. M17 calls the owning service and never writes audit_events directly. Metrics must not claim a committed replay before commit; audit failures remain observable without raw payload.

### 4. Redaction contract

Detect PrismaClientValidationError structurally/by safe name without importing Prisma into observability. Output its safe name/classification and a generic validation message, not rendered arguments or its original stack. Sanitize nested causes too; preserve safe code/status. Existing known-request errors must still pass through secret/path redaction and not emit unvalidated meta dumps. No authorization/HTTP error is converted to fake success.

Mask sensitive absolute POSIX paths, Windows drive/UNC paths and file URLs wherever they appear in Error message/stack/cause or plain values. Keep API route templates and useful safe error codes; a lone `/workspaces/:workspaceId/...` route must not become an arbitrary local-path heuristic casualty. Use explicit path-valued fields, file URL/stack markers and known absolute-root patterns, with bounded patterns and regression fixtures. Do not invent a guarantee for every possible unlabelled relative string; document ambiguous relative-path limits. Registered environment secrets and existing token/URL redaction continue to apply before truncation.

### 5. Fatal flush and early worker boundary

Proposed interfaces:

- `LogSink = (line,level) -> void | Promise<void>`; synchronous injected sinks continue working.
- `StructuredLogger.flush() -> Promise<void>` waits for sink completions accepted through the barrier, including the fatal line. Default sink resolves/rejects from stdout/stderr write callbacks. This is OS stream acceptance, not disk fsync or delivery to an external collector.
- `ProcessErrorHandlerOptions.flushTimeoutMs?: number`, proposed default 2,000 ms, validated positive finite integer; exit remains nonzero/default 1 and test target/exit injection remain supported. No unrestricted provider timeout shares this option.

Set the exiting guard before fatal write. Serialize/redact once, invoke logger.write(fatal), then race its flush against the bound. On completion exit nonzero; on write/flush rejection or deadline exit nonzero without printing raw original Error/stack through another channel. Clear timer after completion; timer must remain active while waiting so it actually bounds a stuck pipe. Coalesce later fatal events; they cannot reset the deadline or cause recursive unhandled rejections. Sink promise rejections are observed. No synchronous fallback write that could block beyond the deadline and no claim a stalled pipe received the last line. The bound is a PENDING architectural choice, not already approved configuration.

Worker main imports only the minimal observability API, registers environment redaction and process handlers, then dynamically imports runtime. Nest, reflect-metadata and domain factories move into `apps/worker/src/runtime.ts`. Preserve pollers, configured/unconfigured behavior, SIGINT/SIGTERM cleanup and resource close behavior. Framework logger override occurs after dynamic Nest import; fatal process protection already exists at that point. Use the same fatal path for runtime import failure. Do not add a production environment switch to inject failures or fabricate a healthy worker.

The minimal logger/bootstrap module and Node itself are outside this pre-import protection boundary. A syntax/import failure before that code runs cannot be honestly guaranteed redacted by this process; loader/build integrity remains required. The proposal protects heavy Nest/domain/runtime imports and later failures, not every conceivable process fault.

### 6. Failure and recovery matrix

| Condition/injection                               | Required result                             | Recovery/limit                                      |
| ------------------------------------------------- | ------------------------------------------- | --------------------------------------------------- |
| More equal-ts rows than page size                 | Strict tuple continuation, unchanged body   | Follow exact returned header                        |
| Sub-ms timestamps                                 | No truncation in cursor/keyset              | Preserve PostgreSQL six digits                      |
| Concurrent newer/backdated insert                 | Documented live-feed semantics              | Refresh/restart; no snapshot guarantee              |
| Foreign/malformed/filter-mismatched cursor        | 400 after authorization, no tenant leak     | Restart valid tenant/filter query                   |
| Stop after claim but before paid dispatch         | Fenced PAUSED, no paid attempt/charge       | Explicit resume after clear, within workflow policy |
| Cancel/state change races stop catch              | Pause CAS cannot overwrite winner           | Return safe state/noop; do not resurrect            |
| Concurrent initial stop create                    | One valid mutation; loser 409               | Reload current version                              |
| Prisma validation / path in nested cause          | Safe redacted output only                   | Preserve safe diagnostics, not arguments            |
| Async fatal sink completes                        | Flush before exit 1                         | No fsync/collector-delivery claim                   |
| Sink throws/rejects/never completes               | Nonzero exit by proposed bound              | Last line may be lost; no raw stderr dump           |
| Heavy import/factory throws with sentinel secrets | Installed handler redacts, flushes, exits 1 | No worker success/startup/provider call             |
| Failure before minimal bootstrap imports          | Not covered by handler                      | Build/loader integrity; limitation explicit         |

### 7. Acceptance tests and real failure injection (all NOT RUN)

T24-01 PostgreSQL audit ties > page size and exact microsecond variants, no duplicate/gap in stable fixture; T24-02 live concurrent inserts above/below/passed boundary match documented semantics; T24-03 invalid/foreign/filter cursors, legacy before and array/header compatibility; T24-04 OWNER/tenant enforcement, SQL parameters and existing index plan inspection; T24-05 mid-step trusted stop PAUSED and manual 409 code, cancellation/fencing/resume; T24-06 racing initial inserts yield one winner/409 with no duplicate audit; T24-07 Prisma argument/stack/cause sentinel and POSIX/Windows/file paths absent while route templates stay readable; T24-08 async/sync sinks, rejected write, stalled flush, single deadline and reentrant fatal coalescing; T24-09 transaction-aware audit rollback with M17 replay.

T24-10 source-level bootstrap test injects a rejecting runtime loader into a pure bootstrap seam and proves handler installation precedes that load. This unit test must not depend on pre-existing dist in clean-checkout CI.

T24-11 **post-build real child-process verification**: `node apps/worker/verification/failure-injection.mjs`. Use Node's module loader hooks in the verifier process to throw at the exact built runtime import, Nest import and domain-factory import in separate children. Inject only synthetic sentinel credentials/local paths. Capture exit/stderr, parse the redacted fatal JSON, assert nonzero exit and no provider/worker-ready output. No runtime production test-mode switch, no built-file patching, no live database/provider needed. Include an unhandled rejection after handlers install.

T24-12 verifier also fills/delays a pipe or injects a never-resolving sink to test real bounded exit, with an outer test safety deadline distinct from the proposed 2-second flush bound. Unit fake timers assert the precise bound; real-process checks allow scheduling margin and fail/terminate the child on a separately documented 10-second harness deadline. Never count forced harness termination as a passing worker exit. Record exact scenarios/results after execution. No full-test skip is used to disguise missing build verification.
